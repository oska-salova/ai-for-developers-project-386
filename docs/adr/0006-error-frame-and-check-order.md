# Единая рамка ошибок, фиксированный порядок проверок, тексты — часть контракта

Все ошибки отдаются в виде `{ error: { code, message, fields? } }` с кодами
`validation_error`, `not_found`, `slot_conflict` и `internal_error`, а при записи проверки
идут строго в порядке тело → существование типа → правила слота → пересечение. Поэтому
невалидное тело важнее неизвестного типа (`400`, а не `404`), а неверный `start` важнее
занятого слота (`400`, а не `409`). Машинных подкодов на уровне поля нет: `message` — русский
текст, который интерфейс показывает дословно, поэтому его изменение меняет контракт.

## Consequences

- `fields` собирает все неверные поля за один проход, в порядке полей контракта; клиент
  сворачивает массив в map и показывает сообщения под полями.
- API-тесты проверяют тексты дословно; UI не придумывает своих формулировок для `400`, `404`
  и `409`.
- `409` отдаёт только код и текст, без данных о занявшей встрече.
