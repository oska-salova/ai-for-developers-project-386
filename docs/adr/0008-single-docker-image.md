# Приложение собирается в один Docker-образ, Next.js проксирует API

Next.js (standalone) и Express живут в одном контейнере: наружу открыт только `PORT`, а
`/api` и `/health` проксируются во внутренний Express на 3001. Поэтому браузер обращается к
API на origin страницы, а один образ выбран ради дешёвого деплоя и потому, что фронтенд и
бэкенд меняются вместе.

## Consequences

- Внутренний порт 3001 продублирован в `frontend/next.config.ts` и `docker-entrypoint.sh`:
  менять его нужно в обоих местах вместе с адресом API.
- В браузере `NEXT_PUBLIC_API_URL` не нужен — используется origin страницы; переменная нужна,
  только если API вынесен на отдельный публичный адрес.
- Dockerfile содержит несколько стадий, но одно приложение: разделить сервисы — значит
  пересмотреть rewrites, healthcheck и переменные окружения.
