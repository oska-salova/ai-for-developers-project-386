# Данные хранятся в памяти процесса, без базы

Типы встреч и встречи живут в замыкании `createStore()`, базы данных нет: перезапуск
сбрасывает всё, а приложение рассчитано на один инстанс. Это ограничение учебного проекта,
зафиксированное в README, и именно оно делает возможной атомарность записи без блокировок
(см. [ADR-0005](./0005-first-wins-synchronous-insert.md)); требование персистентности или
второго инстанса отменяет оба решения.

## Consequences

- Горизонтальное масштабирование и деплой в несколько реплик невозможны: у каждого процесса
  своё состояние.
- Тесты получают свежее хранилище на каждый сценарий, поэтому не нуждаются в очистке данных.
- Демо на Render после простоя стартует без записей, но с одним типом встречи «Знакомство»:
  точка входа сеет его при каждом старте ([#33](https://github.com/oska-salova/ai-for-developers-project-386/issues/33)).
